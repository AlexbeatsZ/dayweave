# Architecture Principles

- Settings controls belong only to global Settings: local capture enable/disable, capture status, permissions and sampling/privacy configuration must not be added to the timeline as shortcuts or prompts. Timeline has no device dropdown or top column-identification bar; keep source modes, dates and record actions. Do not add explanatory copy, summaries or replacement labels to compensate.
- Keep the final architecture simple and clean. Merge new behavior into the existing domain and persistence path; remove obsolete implementations when replacing them.
- One owner for each state: the unified store owns saved data, the shared responsive shell owns navigation, and the timeline owns its scroll window. Derive views and statistics instead of mirroring state through subscriptions or effects. Breakpoint changes adjust layout without remounting the application.
- Reuse one implementation for the same behavior across tasks/records and phone/desktop: modal focus/back, tab/swipe switching, add buttons, clocks, time ranges and goal progress. Avoid parallel helper functions with different names for the same rule.
- Extract a module only when it concentrates real behavior used by multiple callers or isolates a complex cohesive concept. Do not add pass-through wrappers, speculative layers, generic frameworks or files solely to reduce line counts.
- Preserve epoch-based timing, selected schedule timezone, historical point rates and existing data compatibility. Refactors must keep UI/API/sync writes on the same validated transaction queue.
- Delete dead navigation/CSS/functions in the touched area; keep ownership and necessary design decisions in docs/design/architecture.md. Verify through real user flows, especially scroll dates/points and native back, rather than tests mirroring implementation details.

# Durable Lessons

- Android Gradle 8.14 on this Mac: javac needs JDK 21+ (Homebrew 17 fails with `invalid source release: 21`), but Groovy build scripts cannot compile on the Studio JBR (Java 25, `Unsupported class file major version 69`). After any build.gradle change, compile scripts once with `JAVA_HOME=/opt/homebrew/opt/openjdk@17 ./gradlew help --offline`, stop the daemon, then run `JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home" ./gradlew testDebugUnitTest --offline` from `android/`. Do not install or switch the global JDK.
- `tests/fixtures/platform-contract.json` is read by both `tests/platform-contract.test.ts` and Android `PlatformContractTest`: sync addresses, the usage envelope AAD, widget course expansion and school-browser URLs/errors. Change both implementations together and regenerate the fixture only for an intentional protocol change.

- ical.js 2.2.1 normalizes implicit yearly February 29 to March 1 on non-leap years. Add RFC default BYMONTH/BYMONTHDAY before iteration. Normalize minute and zero-second DTSTART forms to one occurrence key before allocating IDs. See arrangements.md and arrangements.test.ts.

- A Windows build from a temporary checkout can typecheck with node_modules junctioned to another checkout while electron-builder silently omits transitive packages. Use real project-local dependencies for packaging and smoke the packaged executable before upgrading users.

- owner.lock written before the current boot is stale whatever its PID now names (a reused PID once blocked Mac startup: 0.5.3 deployment, PID524 reused by accessoryupdaterd). Since the 2026-11-13 runtime fix, startup moves such locks, and unreadable locks older than 5 s, to `owner.lock.stale-<ms>`; desktop shows an error box instead of idling invisibly. Installed builds before this fix still need the manual procedure: quit normally, verify the recorded PID's executable and that no other Dayweave owns the profile, then preserve/move the lock.
- The hub validates client base keys against what `toDocument` emits; new synced collections must go through `isDocumentKey` (src/sync/document.ts). A missed collection makes every dirty client get HTTP 500 while clean clients look healthy.

- Chrome withholds touchmove inside its ~10px touch slop but still sends pointermove; a long-press gesture that only watches touchmove will not cancel on small movements. `useSortDrag` therefore also cancels on touch pointermove before activation. Time click suppression with performance.now(), because e2e tests fix Date.

- On OMEN, `npm ci` deletes the Electron binary and its postinstall download uses Node fetch, which ignores HTTP(S)_PROXY unless `NODE_USE_ENV_PROXY=1`; set it only for `node node_modules/electron/install.js`, because it also proxies loopback admin requests and breaks `test:server`. The server tests run the bundled package, so run `npm run bundle:server` (or dist:server) before `npm run test:server` after a version bump.

- Local e2e on this Mac: project-only Chromium headless shell is installed; use `PLAYWRIGHT_BROWSERS_PATH="$PWD/.local/playwright"`. System Chrome157 was much slower than the matching headless156 runtime. Stop any preview dev server on 5178 first, otherwise reused-server runs fail with "数据尚未载入". With system Chrome the desktop "mouse exposes an edit action…F2" timer test fails on unchanged code too (macOS keyboard focus), so judge it against baseline.

- A fixed-port API can answer from the new server before startup has refreshed api.json's old PID. Deployment acceptance must use /server/status live PID and wait for refreshed api.json to agree before CIM/process metadata checks; an empty old-PID CIM result must not be treated as the new server failing. The first0.1.1 attempt safely restored the old program without data rollback; the corrected PID check enabled the successful retry.

- Windows scheduled-task Priority is independent of S4U/Session0: official6 maps to Normal/Normal I/O/Medium memory, default7 to BelowNormal/Low I/O/Low memory. Full usage status can scan historical JSON rows; rapid repeated probes can queue behind those scans. Use lightweight /health and validate real task priority before attributing slow startup to corrupted data or changing ownership/architecture.

- Windows OpenSSH helpers run in Session0; cooperative Restart Manager shutdown of the interactive Dayweave process returned350 there. Running the same flags0 request in the existing Session1 tool host succeeded without forced termination. Check process sessions and visible windows before concluding the app refuses graceful shutdown; retain the hub task action rather than replacing it.

- School refresh ownership is a recovery journal, not just the IDs in the optimistic view: retain old/new IDs until the business save queue is healthy, even for no-op refreshes. Pause refresh throughout explicit import preview/confirmation.
- Save timestamps/segments, never tick counts. Storage corruption must remain recoverable, never silently become empty state.
- All UI and API writes share StateService; module changes have optimistic conflict checks.
- Zod defaults can survive .partial(): PATCH schemas must explicitly remove defaults for optional configuration fields (e.g. periods), otherwise an unrelated write silently resets saved configuration.
- Xiaomi widgets have a separate :widgetProvider process and must read persisted app-private data without launching the WebView.
- For sideloaded builds, omit Xiaomi-market miuiWidget/miuiWidgetVersion markers: the standard Android picker then exposes both variants on the tested Pad 6 Pro. A successful requestPinAppWidget result does not prove Xiaomi showed a confirmation; keep manual picker instructions.
