# 数据与持久化

- `src/model.ts` 定义独立的版本 1 数据格式，Zod 在读取、导入和桌面写入前验证。ID 唯一、清单关联合法，非法日期和重复引用被拒绝。导入使用合并策略，按更新时间选择同 ID 任务，保留本地设置与运行中的计时器。
- 桌面主进程保存到独立 Dayweave 用户数据目录的 `data.json`。写请求串行执行，临时文件先落盘并 fsync，然后在同目录 rename 替换；上一份有效文件保留为 `data.backup.json`。损坏时仅自动读取通过校验的备份，并保留原损坏文件；无有效文件时阻止编辑，提示恢复。
- 渲染器通过白名单 preload 方法调用 IPC，启用隔离和沙箱，不接收任意路径或任意 IPC 通道。导入导出由原生文件选择器决定路径。
- 浏览器预览使用独立的 localStorage 命名空间，明确提示浏览器数据与桌面版分开。桌面不能写入时必须显示错误并保留内存中的数据，不能伪称已保存。
- 日期是本地日历日 `YYYY-MM-DD`，不能用 `toISOString().slice(0, 10)` 推算今天。UTC 时间戳只记录事件时间。月重复按原始锚点日截断到目标月最后一天；重复实例只生成一次。删除已生成实例不会在重复完成时自动补回。
- 专注使用截止时间而非累计 tick，应用休眠和重启后可恢复。完成计时后按计时器 ID 去重记录一次。暂停记录剩余秒数；取消不计入专注统计。休息计时不计入专注时长。
- 关闭桌面窗口前等待渲染器发送的保存请求队列完成，写入失败时让用户选择保留窗口继续处理。

## Dayweave 0.3 扩展

同一文件增加 timelog 与 schedule，旧 Clearlist 文件读取时补齐字段。默认日程时区 Asia/Shanghai，日期规则不再使用设备日界线。时区入口 src/timezone.ts；课程和导入规则见 integration.md。各模块通过同一个 StateService 保存，实体数组按 ID/字段合并，设置和标签颜色按字段合并；独立编辑不再因整个模块变化而冲突。计时器与其他配置值保留原子比较，真正的同字段竞争、删除与修改、并发重排必须明确报冲突。数值更新时间取较新值，可选字段删除也必须传递。

渲染器 `store.transact` 在发布修改前执行转换和格式校验。可恢复的业务拒绝（如过短计时或过期编辑）只向调用方抛错，不写入全局磁盘故障状态；真正的持久化失败仍保留待保存队列、显示错误并等待恢复。

## 保存与损坏恢复

共享 StorageRecovery 区分乐观冲突和存储失败，提供导出未保存内容、重试和重新读取入口。失败时冻结新增乐观编辑，保留原队列；initialize 不得清空队列。重新读取必须先由用户确认放弃，或成功导出候选，且新状态成功读取/校验后才能清队列。取消导出、读取失败都不能丢弃候选。

初次读取失败不能永久缓存 rejected Promise。备份恢复与其他写操作共用 StateService 队列，校验后写入、通知订阅者并重新调度截止计时。浏览器恢复同样先校验，保留原 primary/backup 的 before-restore 副本；原生恢复继续使用现有文件选择器和存储恢复路径，不创建第二套持久化实现。
