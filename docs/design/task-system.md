# Task + dates + Cron

2026-11-05 用户最终需求与本轮后续纠正。任务难度取代工作量，旧任务统一为简单；预计/实际分钟与记录均独立保留。用户已授权部署；中心与客户端采用 schema/protocol 2，迁移保留身份和原始恢复检查点。

## 字段清单与迁移

原 Task 全部字段：`id`、`title`、`notes`、`estimatedMinutes`、`actualMinutes`、`effort`、`listId`、`due`、`tags`、`planGroupId`、`subtasks`、`repeat`、`repeatDay`、`spawnedId`、`parentId`、`pinned`、`order`、`createdAt`、`updatedAt`、`completedAt`、`deletedAt`。

- 原样保留标题、描述、预计/实际分钟、清单、标签、置顶、顺序、四个时间戳及软删除。
- `due` 与任务级 `planGroupId` 合并为 `dates`；失效时段清为 null，日期保留。∞ 必须为 null，空映射为待办箱。
- `effort`/旧 `priority`/`quadrant` 退出模型。v1 数据全部迁移为 `difficulty: easy`。v2 新任务默认 easy，medium/hard 手动设置并显示样式，绝不从时长推导。
- 子任务保留 ID、标题、done；增加可空完成时间、软删除和轻量 `{id, at, done}` 事件。旧完成时间未知时保持 null，不伪造日期。
- 四个旧重复链字段迁移为顶层 `repeatRules`，以 prefix 为主键；不增加系列身份。v2 Task ID 为随机 UUID 前缀 + 整数后缀。
- v1 任务统一确定性转换 ID：独立任务以旧 ID 的 UUID v5 为前缀、后缀 0；重复链以根 ID 派生同一前缀，按链深度分配序号。只用旧 ID/链关系，不用标题。全部 sessions、旧 timer、timelog records、timer、conflictedTimers 的 taskId 同步改写。迁移函数幂等；原始备份可通过离线迁移工具审查映射。分叉或环形重复链拒绝迁移，保留原文件供修复，不能悄悄丢任务。

## 领域、历史与投影

所有保存入口在原队列中执行同一完成规则。显式完成/撤销父任务改变全部现存子任务；普通子任务编辑重算父任务。空子任务列表不自动完成。同步后的父状态由合并后的子任务重算。

完成/撤销事件记录事实，不清除之前日期的事件。过去日视图仅展示该日事件和关联执行记录，并保留当日安排；没有旧时间戳不推测。今天展示未完成部分及今日发生的完成事件；总视图展示完整子任务。

总视图只包含未完成且 dates 有今天/未来/∞ 的任务。日视图严格按 key 查询，待办箱为空映射；历史任务从其日视图打开后可重新添加日期。任务页只有日视图、总视图、待办箱，不提供周计划、全部或搜索框。没有逾期、结转或自动迁移。总视图按 ID 前缀只显示一条实际任务行，不再有展开列表。先排除已完成、已删除、没有今天或未来日期的循环候选，再按 ID 后缀的数值取最小实例；给昨天的旧实例手动加今天日期后，它重新参与编号比较。完成当前实例后从既有任务重新投影下一项，不创建新任务，也不改 Cron/完成逻辑。循环样式仅由是否存在同前缀且编号更大的任务决定，不检查 Cron 配置或模板；没有更大编号的最后一项用普通确认圈。日视图/月历继续显示所选日期的实际 Task。

### 有限循环与 Cron 的区别

循环显示由实例 ID 之间的关系决定：存在同前缀、数字后缀更大的 Task，当前任务就是有后续实例的循环任务。Cron 只负责按规则继续生成未来实例，不是判定循环样式的依据；是否有规则、规则是否启用都不能替代实例关系。

例如用户只准备执行 30 次，可让 AI 一次创建 `prefix-0` 到 `prefix-29` 共 30 个普通 Task，分别安排日期，不创建任何 Cron 规则。前 29 项有后续编号，使用循环箭头；第 30 项没有更大编号，使用普通圆圈。总视图每次只显示符合今天/未来日期条件、未完成且编号最小的一项，完成后显示下一项。第 30 项完成后自然结束，不补造第 31 项、不要求用户停用规则。这个有限系列与 Cron 自动生成的系列复用同一 Task、日期及完成路径，不引入新的类型、系列字段或独立生成机制。

## 日期选择交互

编辑器仅提供今天、明天、待定、无日期、更多五个快捷项。今天、明天、待定再次点击取消；待定直接对应 `∞: null`。无日期清空整个映射，可以只填标题直接保存到待办箱。没有开始/结束日期或必填日期。更多打开多选月历：左上年月、右上圆形∞，日期与∞同大小、同样式，选中蓝色，再点取消；左右滑动切换月份，桌面也可用前后月按钮。月历和快捷项直接修改同一份 TaskComposer 草稿，关闭不丢选择，外层保存前不写盘。具体日期仍能各自选择原有时段。连续多日通过连续选择日期输入，保存仍为日期键集合。

## Cron 与中心

复用 cron-parser，公开支持确定性的五字段 Cron（分钟、小时、月日、月、星期；禁用 H/@/秒字段），月日与星期不可同时指定。遵循其时区/DST 行为；触发 instant 用项目业务日规则转换为日期，再按 dateOffsets 展开。日期窗口默认 14 天，可请求至未来 366 天；每轮生成有数量限制。

唯一中心通过 StateService.mutate 串行生成，规则的触发→实例字典与新 Task 同次落盘。重试、重启与删除已生成任务均不补造重复实例。模板与实例独立；停止只关 enabled，不删实例。客户端离线不生成；扩展窗口请求沿原认证加密同步通道发送。

## 同步、升级与恢复

业务状态版本和加密业务交换协议升到 2（usage/配对凭据不变）。中心拒绝旧业务协议，客户端拒绝旧响应；升级中显示版本不兼容，保留本地编辑、原始 sync 基线、配对和冲突候选。v1 基线用相同完整状态迁移后再比较，迁移不被识别为用户删除/新增。

dates 按 key，subtasks 按稳定 ID、再按字段，历史按事件 ID 三方合并。真正的任务字段冲突由中心本次接受操作胜出，不使用客户端墙钟；独立字段保留。任务/子任务软删除优先于旧修改，只有基线中已知删除后的显式恢复才能撤销删除。本地乐观保存仍保留并发冲突提示与 API If-Match。

备份导入保留较新的重复配置及模板，合并双方的触发账本。同一配置保留更远的生成游标；Cron/startAt/偏移已变化时使用新配置自己的游标，避免旧游标跳过新周期。OpenAPI 直接描述原始 v2 对象 schema，运行时仍经迁移及领域校验，不把转换包装器导出为无字段对象。

发布顺序：完成预览审阅后，冻结旧端写入并保留原始 profile + sync.json → 先升级中心 → 全部客户端 → 验证配对、记录 taskId、任务/时段与真实离线双端合并 → 恢复自动化调用。AI Decision 调用方也需改 dates/难度。不得让旧端与新中心继续混写。
