# ROG 同步中心与计时记录

## 用户决定

2026-10-20 用户选择 ROG 作为常在线同步中心，并授权在 Redmi K70 安装独立 APK。Windows/macOS/Android 离线可用，同一局域网通过 DNS-SD/mDNS 发现 `_dayweave._tcp`；首次明确配对后再自动同步。发现失败保留手动地址入口。

## 唯一记录与计时

同步文档只有一类时间记录。`timing.startAt` 为开始时刻，`endAt:null` 表示未结束，`runningSince` 和已完成 `spans` 表示运行或暂停。停止给相同 ID 补上结束时间，绝不另外创建一条无关记录。UI 兼容适配原 Timelog 的 timer/records，因此旧备份和时间线操作仍可用；协议以统一记录为准。各端按 UTC epoch 计算有效时长，不同步每秒 tick，不受显示时区影响。

结束状态优先于滞后的运行/暂停状态；晚到的旧设备消息不能恢复已停止的计时。离线同时开始的不同 ID 均保留，主计时和冲突计时明确展示，用户可分别结束，不能静默删除其中之一。

## 同步事务

中心唯一写入队列继续使用 StateService。客户端持久保存最后同步的基础文档；本地数据是离线修改队列的事实。请求仅在本地发生改变时发送基础文档和当前状态；没有改变时只轮询中心 revision。中心按实体与字段做三方合并，新增任务/记录彼此独立，冲突保留中心值并返回本地候选供明确处理。

响应应用前保留请求期间新增的本地改动，再保存新的基础文档。Android 当前在应用打开和恢复前台时自动同步；系统冻结后台 WebView 时暂停网络交换，下次打开后补齐。当前没有原生后台同步任务，因此没有跨进程覆盖主文件的路径。计时时长始终由时间戳恢复；组件独立刷新已同步到本机的课程。

## 发现、配对与传输

桌面使用 bonjour-service，Android 使用 NsdManager。广播只有服务名称、中心 ID 和端口，不含用户数据或凭据。LAN 同步端口与 loopback AI API 分开。首次邀请具有高熵随机密钥和短有效期；配对和后续载荷用 AES-256-GCM 加密并验证路径/客户端身份，明文 HTTP 不承载任务、课程或配对密钥。客户端每次持久增加请求序号，中心在处理写入前持久保存已接受序号以拒绝旧包重放。

设备凭据、配对邀请和同步基础文档保存为应用私有同步配置，不进入用户备份、Git 或 Release。首次开启中心不会修改 Windows 防火墙或全局网络设置；若系统规则阻止入站，需要单独授权修改。中心可在 ROG 以无界面 Node 进程运行，AI API 访问该中心同一份数据。
