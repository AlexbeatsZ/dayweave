# ROG 同步中心与计时记录

## 中心与离线数据

用户选择 ROG 为常在线同步中心。Windows、macOS、Android 可离线编辑，同一局域网通过 DNS-SD/mDNS 发现 `_dayweave._tcp`，首次明确配对后自动同步。发现失败保留手动地址入口，不依赖全网段扫描才能使用。

ROG 的 LAN 同步、loopback AI API 和桌面 UI 共享 `StateService` 与同一份经过校验的状态。中心可无界面运行，也可使用桌面 `--tray` 模式；当前产品要求登录后启动到托盘，不弹主窗口。AI 决策系统操作同一份任务和计时，不把旧 Todo/UpTimer 作为另一套运行时依赖。

## 一条记录从开始到结束

同步文档以 `records/<ID>` 表示同一类时间记录。`timing.startAt` 是开始时刻，`endAt:null` 表示未结束，`runningSince` 与已保存 `spans` 表示运行/暂停。停止给同一个 ID 保存结束时间和片段，不新建无关记录；前台 `timer/records` 只是这一表示的适配。

计时可携带 `taskId`、描述、标签、开始时锁定的性质与积分速率。可选 `timing.plannedEndAt` 是倒计时截止；它不能冒充已结束记录的 `endAt`。各端根据 UTC epoch 和有效片段计算累计/剩余时间，不传每秒 tick，不因显示时区不同而改变时长。

暂停保存有效片段并冻结剩余时间，继续按暂停持续时间顺延计划截止。前台和中心共用 `finishDueTimer`，到期用同一 ID 按原截止保存；晚唤醒不会把截止后的时间补进记录。中心在加载、读写和截止调度中校验到期。客户端离线时也可在下次前台恢复后收尾，随后交换结束记录；重复收尾不得形成第二条记录。

结束优先于滞后的运行或暂停状态，晚到旧消息不能恢复已停止计时。离线同时开始的不同 ID 全部保留，主计时与冲突计时明确展示，用户分别处理，不能静默删除候选或自动把冲突计时结算为任意结果。下一个活动在一次本地事务中保存旧 ID、开始新 ID，两者边界为同一时刻，随后通过同一文档同步。

## 配置与颜色也是数据

- 清单实体携带 `color` 与可选 `activityId`，默认任务计时映射为学习 → 学习、工作 → 实操、生活 → 日常。显式绑定按活动 ID 保存和同步，默认名称规则仅用于未配置绑定的选择；UI 和 AI 使用同一领域入口。
- 活动实体保存自身 `color`；删除后的历史活动身份必要时用 `deletedAt` 保留，以解析旧记录。删除不变成可恢复的归档入口。
- `tagColors.tasks` 与 `tagColors.records` 分别保存两类标签颜色，在同步 preferences 中表示为 `taskTagColors`、`recordTagColors`。它们和标签内容、清单映射都进入完整备份与增量保存。
- `timelog.settings.timerPresets` 与更新时间同步为 preferences 中的 `timerPresets`、`timerPresetsUpdatedAt`；预设未提供时新程序补默认 `[5,30,45,60]`，显式空数组不能被当作缺失覆盖。
- 日程时区、学期、课程和事件继续参与文档；本机主题与配对凭据不混入共享业务配置。任务 `due=null` 决定待办箱，所属清单与计划日期分别同步。
- 任务 `estimatedMinutes`、`actualMinutes` 是各自独立的可空字段，不自动由关联记录写回。节次 `schedule.periods` 作为课程标尺配置同步，和课程本身的 HH:mm 分开；编辑节次不移动已保存课程。

## 三方合并与保存

客户端持久保存最后同步的基础文档。本地状态保留离线改动；数据改变时发送基础文档和当前文档，没有改变时只查询中心 revision。中心在唯一写入队列中做三方合并，独立新增实体彼此保留，实体字段分别合并。

同一字段两端各自修改时保留中心值并返回本地候选，供明确处理；同一标签颜色映射或计时 timing 也受此规则约束，不宣称任意深层字段都能自动合并。结束优先是计时的明确例外。删除与另一端修改相遇时报告冲突，不能凭缺失值静默丢弃修改。

应用响应前保留请求期间新增的本地改动，再保存新的基础文档。所有结果经过统一状态校验，不能直接绕过保存队列覆盖主文件。并发编辑表单继续使用任务更新时间或状态 revision 检查，不因同步到来而偷偷覆盖草稿。

Android 当前在应用打开、前台运行与恢复前台时自动同步；系统冻结后台 WebView 时暂停网络交换，下次打开补齐。没有原生后台同步任务，不承诺后台即时传播。小米组件独立刷新已经提交并同步到本机的课程数据，不启动 WebView 获取远端更新。时间显示可从时间戳恢复，不意味着网络交换也在后台执行。

## 发现、配对与传输

桌面使用 bonjour-service，Android 使用 NsdManager。广播只含服务名、中心 ID 与端口，不含业务内容或凭据。LAN 同步端口 49732 与 loopback AI API 49731 分开。首次邀请使用高熵随机密钥与短有效期；配对及后续载荷使用 AES-256-GCM，并验证路径和客户端身份，明文 HTTP 不承载任务、课程或配对密钥。客户端持久增加请求序号，中心在处理写入前持久保存已接受序号以拒绝重放。

凭据、配对邀请和基础文档保存在应用私有同步配置，不进入用户备份、Git 或 Release。启用中心本身不修改防火墙或全局网络设置，入站受阻时另行获得系统修改授权。

邀请可为原始 JSON 或 `dayweave://pair?invite=<base64url UTF-8 JSON>`。Android 深链接只预填配对设置，仍需用户点击配对，链接不能自动上传本机数据。设备名根据原生型号及最小屏幕宽度区分手机/平板；已接受请求可更新中心保存的名称。桌面优先 Wi-Fi IPv4 并绑定对应接口，Android API 34+ 检查完整 host address 列表选择 IPv4。

## 版本兼容与验证边界

统一状态仍为 schema 1，新程序读取缺失新字段的旧备份时补默认值，这只保证向后读取。旧应用/中心的严格 schema 可能拒绝新增清单映射、标签颜色或预设，旧计时适配还可能丢失 `plannedEndAt`。不能把旧备份可导入当作混用旧客户端可安全同步。

发布新增字段前，ROG 中心和手机/平板需更新到支持同一契约的版本，保留原 profile、配对和密钥；未更新设备不得标记为已验证新功能。APK 生成、签名或单端浏览器通过都不能证明真实跨设备同步。

分别记录三方合并、结束优先、离线并发启动、截止和配置往返测试；加密/重放测试；真实双客户端与 AI 调用；Android 前后台、断线、重启；小米组件刷新和 ROG 常驻行为。自动 mDNS 发现、实际后台边界、物理设备上未执行的项目保持未验证。
