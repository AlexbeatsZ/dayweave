# 手机界面与交互

## 范围与视觉

`src/phone/MobileApp.tsx` 是全部宽度共用的页面入口。视口宽度不超过 700 CSS px 时显示手机底栏与抽屉，更宽时显示 PC 常驻侧栏和宽内容区。两者共用页面状态、编辑草稿、数据模型、store、保存、同步和主题，缩放窗口跨断点不会重挂载应用或丢失当前子页、计时及草稿。

空间安排参考用户提供的 Sefirah 与 UpTimer 截图：周日期条、任务底部面板、记录时间边界、活动圆环和双列目标。只借鉴布局与操作线索，不复制截图资产、品牌色或原程序代码。

普通背景使用中性灰、正文使用白色或浅灰，统一冰蓝强调色只用于主要操作、选中项和运行提示。

| 用途           | 暗色值            |
| -------------- | ----------------- |
| 页面底色       | #181818           |
| 普通卡片/面板  | #252525           |
| 输入与次层容器 | #202020           |
| 分隔线         | #3c3c3e           |
| 正文/次级文字  | #f4f4f5 / #adadb2 |
| 强调色         | #76b9ed           |

清单、待办标签、活动、活动标签均可自定义颜色，颜色用于确认框、色标、标签和图表，不大面积填充普通容器。浅色模式与跟随系统的偏好继续保留。网页预加载、Electron 背景、Android 启动屏及原生组件使用一致灰阶。

## 导航与侧栏

顶部第一行是菜单按钮与较大的页面标题，第二行放当前页的子页。待办标题不再与子页挤在同一行。顶部不放搜索或主题按钮；外观与时区在设置内修改。

| 全局底栏 | 第二行子页                      |
| -------- | ------------------------------- |
| 待办     | 日计划 / 周计划 / 全部 / 待办箱 |
| 记录     | 时间线 / 计时 / 目标            |
| 安排     | 月历 / 课程表                   |
| 统计     | 每日 / 待办 / 记录              |

子页支持点击与左右滑动，二者修改同一导航状态，使用短暂的位移与淡入过渡，尊重减少动态效果偏好。水平手势必须明显大于垂直位移；输入、编辑、弹窗、任务拖动期间不触发切页。普通纵向滚动不切页。

三条杠菜单打开左侧栏，不增加滑动呼出侧栏的手势，避免与子页切换冲突。待办侧栏显示所属清单、待办标签；记录侧栏显示活动、活动标签；这些项目可新增、编辑颜色和删除，也可点击筛选。设置与同步入口固定放在侧栏内。其他页面仍可由侧栏打开设置。没有独立的更多、已完成、回收站、四象限或番茄钟页面。

PC 左侧栏始终显示，不提供折叠按钮或顶部汉堡入口。主导航固定为待办、记录、安排、统计，下面复用同一个上下文分类组件，设置放在侧栏底部。标题与子页沿用手机层级，主体按可用宽度展开：周计划可按日期多列排列，课程表按设置展示五天或七天，统计与目标使用合适的多列卡片，普通任务行与正文保留适当最大宽度。适配 16:10、16:9 及较窄 PC 窗口；编辑面板在 PC 居中、手机从底部弹出，字段与保存逻辑相同。

## 计划范围与任务排列

- 日计划使用周日期条切换日期，支持前后周、任意日期与今天。今天可包含此前尚未完成的逾期任务；历史日期按该日计划查看。所有日期按设置的日程时区判断。
- 周计划显示所选日期所在的自然周，即周一至周日，合并这一周的日计划；不能实现为从今天开始向后滚动七天。周内任务按日期分组。
- 待办箱只判断任务的计划日期是否为空，任何清单内没有计划日期的未完成任务都属于待办箱；有了日期便进入相应日计划、周计划。它不是一个所属清单。兼容数据中的默认 `listId="inbox"` 在清单选择中称为“未分组”，不能再显示为收集箱或待办箱，也不列入侧栏的自定义清单。
- 四象限是日计划与全部内部的展示选项，复用紧急/重要判断，不增加全局或子页入口。
- 未完成任务的确认框使用所属清单颜色，框内显示当前视图中的顺序数字，从 1 连续排列。数字表达用户安排的处理先后，不是永久任务编号，也不由红黄紧急程度自动决定。筛选、完成、拖动后按当前可见的未完成任务重新编号。
- 紧急程度显示为任务行左侧竖线：优先级 1 为红色，2 为黄色，3 和 4 无竖线；不再用确认框颜色同时表达优先级。
- 长按任务进入拖动排序，拖到另一项位置后持久化任务顺序，尚未进入拖动时取消不改数据。滚动手势不会立即抓起任务，拖动也不能误开编辑、完成任务或切页。
- 仅日计划和周计划保留已完成任务：灰色文字、确认框打勾，沉到未完成任务之后，不占未完成序号。全部、待办箱、清单、标签等其他任务范围隐藏已完成任务，避免不断积攒。
- 子任务在父任务下缩进显示，普通列表、日/周计划、四象限及清单/标签筛选都可直接勾选；完成后保留在父任务内，以灰字和删除线表示。父任务与子任务、列表与编辑面板共用 `TaskCheck` 的大小、形状、清单颜色及键盘行为，子任务不占父任务的优先序号。列表内勾选立即走统一 store 更新最新任务；只更新对应子任务的完成状态，不自动完成父任务，也不能误开编辑、计时或拖动。

## 一个任务编辑面板

新建和编辑复用 `TaskComposer` 的同一个视图与字段：清单、标题、描述、计划日期、标签、子任务、优先级、重复。编辑只填入已有值并增加相应操作，不另建一套任务详情表单。标题中的 `#标签` 与独立标签输入合并去重。

预计用时与实际用时也在同一面板中编辑，单位为分钟，两个字段均可留空，允许零值与小数。清空后保存为空值，不能把留空视为零。实际用时留空且存在已保存的任务关联记录时，另外显示只读的“关联记录累计”，不把计时记录自动写回实际值；未结束计时和已删除记录不计入这个参考值。任务行仅在有显式值时紧凑显示预计/实际，不给空字段预留一行。重复任务沿用预计值，下一次实际值留空。

草稿仅存在面板内，只有显式保存成功才关闭；取消不写入。编辑保存读取最新事务中的任务，以打开时的 `updatedAt` 检查并发变化，不能覆盖另一设备或 API 的新修改。业务拒绝或保存失败保留输入并显示原因。删除不引入归档功能；底层删除标记用于同步和恢复，不重新开放回收站页面。

编辑面板内的子任务勾选仍只修改草稿。子任务的完成按钮不使用原生文本输入样式；新增子任务的文本框样式仅作用于 `.subtask-entry-input`，不能再把确认框拉伸到整行。

任务旁的计时按钮保留。所属清单可设置默认活动映射，任务启动计时与 AI API 共用同一入口，保存任务 ID、标题描述及任务标签。默认映射为学习清单 → 学习活动、工作清单 → 实操活动、生活清单 → 日常活动；显式活动绑定优先，绑定失效时提示重新选择，不能悄悄计入其他活动。

## 时间线、计时和目标

自动/对照时间线不按设备固定分列，所有设备在同一个自动记录区域内并排显示重叠卡片。360 / 390 / 430 CSS px 都不允许页面或时间线内部横向滚动；宁可卡片窄到文字省略，再点击查看完整详情，也不设最小列宽或横向滚动条。不恢复顶部标识、设备筛选或采集设置入口。

时间线按结束时间倒序显示，每个有效片段独立成卡，保留暂停空隙。空档可直接补记。接近底部时自动加载上一天，短列表自动填充可滚动空间，没有“查看更早一天”按钮或七天上限。

时间线复用日计划的日期控件快速跳转。跳转重设浏览窗口，普通滚动只更新当前可见日期；不放每日记录摘要或空闲显示选项，记录时间与积分放统计页，不展示积极时间。编辑、删除或填满空档显式携带记录所属日期，不能误用今天或跳转锚点。目标页面没有日期切换，按当前日与自然周展示。

计时未运行时只有分组活动与“＋”新建卡片，长按活动编辑；不显示管理活动、正计时预设或起止控件。开始后显示时间圆环、暂停、预设、起止摘要和关联内容，操作行集中下一个活动、完成与取消。计时使用开始时间、有效片段与可选结束时间：没有结束时间为正计时，未来的结束时间为倒计时，过去的完整起止范围保存为已结束记录。默认倒计时预设为 5、30、45、60 分钟，后面的加号进入预设管理，可新增或删除，保存后参与备份和同步。倒计时截止按同一个记录 ID 保存，暂停后继续相应顺延截止时间，延迟恢复不能多算截止后的时间。

调整起止时间在同一面板内完成，“上一条记录末尾”仅放在开始时间调整处。计时保留相关标签、活动内容和相关计划，相关计划可绑定今天日计划内的任务。下一个活动先选活动，再于同一事务、同一时刻保存当前活动并开始下一项，避免衔接空档。离开计时页后保留运行栏，时间由时间戳恢复，不保存每秒计数。番茄钟及其设置、入口均移除。

目标参考 UpTimer 的每日/每周分组与双列紧凑卡片，显示组内达标数、活动图标、剩余时长、百分比，点击编辑，菜单直接删除。没有归档、结算、商店或新增奖励规则。待办、记录、目标的加号统一使用 `FloatingAdd`，尺寸、圆角、图标、颜色和安全区域位置一致。

## 安排与统计

安排包含月历和课程表。月历按日期查看计划；课程表保留课程导入、学期与周次、地点、下一节课和日程时区计算，小米组件继续读取已同步到本机的数据。

课程表主体是按星期列、真实上课时间纵轴排列的二维周表，顶部仅保留周导航；课程块高度与位置按实际时间计算，不因节次数量等分。点击课程使用同一课程编辑面板；空白时段先选中，再点选中区域进入新建，并预填星期、起止时间。右下角统一加号打开课程操作菜单，提供网站导入、文件导入、手动添加，学期/时区、节次、导出等次要操作集中在菜单中。网站读取及文件导入仍经过预览与确认。

课程表的全部星期列必须同时显示，手机 360 / 390 / 430 CSS px 宽度也不能依赖左右滚动。窄列优先显示换行课程名和地点，完整时间、教师等仍可点开同一个编辑面板查看。课程操作 → 更多 → 学期与时区内可选择课表显示天数：默认自动，无周末课程时显示周一至周五；整个学期存在实际周末课程或日历安排时显示七天，未来周次的周末课程也会计入。改为固定五天或固定七天即可关闭自动判断，选择随课表保存、备份及同步。固定五天不会删除周末安排，不影响下一节课与组件计算。

点击左侧节次标尺或菜单内“节次设置”进入同一设置面板，可调整上午、下午、晚上的节数及每节上课/下课时间。某段可以为零节，但全天至少保留一节，最多 30 节；节次按分段和时间排序且不可重叠，可前后相接。节次设置保存到 `schedule.periods` 并参与同步；修改标尺不能挪动或改写已有课程的真实时间。旧课表缺少该字段时使用独立的默认节次副本。具体 schema、增量与 API 边界见 integration.md。

统计的每日页结合所选日期的计划任务、当天完成任务和记录时长/积分，可跳转该日时间线；待办页统计全部未删除任务；记录页统计全部已保存、未删除记录，不受 7 天或 30 天窗口限制。已完成任务虽然在多数任务列表隐藏，仍参与统计。总时长使用区间并集，活动分布与积分按记录累计，历史性质和积分速率不因活动编辑而追溯改变。

## 返回与验证边界

侧栏、底部面板与时间模块对话框共用原生 `Modal` 的焦点和返回实现。Android 返回先关闭最顶层弹窗，再退出当前编辑或侧栏，最后回到待办或交由原生退到后台；卸载后恢复原焦点。手机使用动态视口、安全区域、内部滚动和固定保存操作。输入至少 16 px，主要按钮至少 44 px，键盘缩短视口后保存仍应可达。

UI、API、同步写入同一校验与保存队列。业务校验错误只拒绝当前操作；实际写盘失败继续提供错误、备份和恢复，不能显示伪保存。倒计时、计划时区与历史计算见 timelog-domain.md；模块归属见 architecture.md；Android 前台/恢复同步和版本边界见 sync.md。

验证按层记录：领域与同步测试、浏览器触摸/滚动/拖动及窄屏交互、打包、真实手机和平板分别验收。浏览器模拟不等于实体键盘、系统手势、后台行为或小米组件验收，安装成功也不等于这些功能已实测。
