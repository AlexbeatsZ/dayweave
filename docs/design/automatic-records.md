# 自动记录：采集、时间线与多设备同步

## 产品与数据边界

手动记录表达「我做了什么」，继续拥有活动、关联任务、历史积分与目标；自动记录表达设备观察，不创建手动记录、不增加积分、不自动完成任务。两个来源在原有「记录 → 时间线」和「统计 → 记录」内切换，不增加第二套导航。

- 时间线三种来源模式：手动、自动、对照。对照左边手动、中间时间刻度、右边所有设备共用一个自动记录区域；自动模式只保留刻度与同一个自动记录区域。不显示顶部列标识栏、设备名/平台标签，也不放设备筛选下拉框。来源身份只合并展示、不改存储或统计身份，沿用时间线自己的日期与滚动窗口。
- 卡片复用现有手动记录的自然高度风格，不提供缩放选择。`timeline-layout.ts` 从全部记录的起止边界生成同一条非等比时间轴：短片段至少留出可读卡片高度，长空档压缩；同一毫秒在左右区域中始终映射到同一纵坐标，显示的起止与时长仍是实际时间。全部设备、应用与网页在当前重叠簇内自动并排，后续无重叠记录恢复整个区域宽度。相同内容的连续采样仍按设备和类型分别合并显示，不改存储或统计。
- 手机必须一次显示全部横向内容，时间线内部也不允许依赖左右滚动。固定窄刻度，两侧区域可缩至零最小宽度，重叠卡片按百分比分摊；宁可密集时文字省略，也不设卡片最小宽度或横向滚动。点击任一卡片通过原有详情显示设备、起止、完整标题等信息；瞬时解锁保留为独立标记。
- 单张记录填满所属区域；交错记录在整个重叠组内保持固定等宽矩形，不按时间片动态扩展宽度。例 `1–4` 与 `2–5` 始终各占一半，`1–2` 的另一半与 `4–5` 的另一半留白，不拆卡、不补宽；该组结束后的独立记录恢复满宽。卡片不再预留额外的横向百分比空隙。
- 所有时间保存 UTC epoch 毫秒，日界线沿用日程时区。Work Review 的秒在适配入口换算，不改原始数据库。
- 自动统计提供当天/近七天/近一月及设备筛选，显示跨设备区间并集、各设备并集之和、应用、来源分类、网站、解锁次数。网页是应用的子层，不能与应用相加；同一设备同一网站的重复观察先求并集。不同设备的应用/网站累计可以超过自然经过时间。
- 自动详情只读。手动列仍打开既有编辑器，并遵守活动/标签筛选；自动列不将手动标签误套为自动分类。
- 时间线不放每日摘要、积极时间、空闲显示选项或解释性说明。记录时间、积分及设备统计只放统计页；记录卡自身的时段、时长和历史积分继续保留。时间线仅保留来源视图、日期与记录操作；本机记录开关、采集状态、权限与采样配置只放全局设置，复用既有开关和权限入口，不在时间线另做快捷设置。

## 唯一所有者与存储

重叠卡片分道复用 `src/interval-lanes.ts`；自动记录保留同起点长区间优先、再按 ID 排序，课程采用自己的短区间优先规则。弹性时间轴、设备来源合并、瞬时解锁标记仍在 usage 模块，不进入共用分道函数。

自动观察沿用私有配对配置中的有序 endpoints，与业务同步一样每轮从首项逐个回退；旧单 endpoint 兼容为一项。桌面复用 SyncClient 的网络尝试，Android 原生队列复用 SyncEndpoint 的顺序规则，不按网络类型排序、不提升已成功地址。事件修订、requestId 与回执校验不变。

`src/usage/domain.ts` 是校验与统计口径；`import.ts` 是历史格式入口；`client.ts` 是 UI 到本机存储的桥。`UsageStore`（桌面）及 `UsageDatabase`（Android）各自拥有本机 `usage.db`（WAL）。自动观察量大且会持续修订，不加入统一业务 JSON，也不经手动记录的 StateService 写入队列。原来任务/手动记录/课程的事务路径完全不变。

事件包含来源 ID、设备来源 ID/显示名称/平台、类型、起止、应用、标题、网址、分类、修订与删除标记。批量导入和同步接收均事务化；旧回执仅确认对应修订，不会清除较新待上传修订。重复观察不重复插入，修订替换会推进交付序号。自动数据库不属于业务 JSON 备份；常规界面不提供 JSON 导入导出或来源载入入口。Android 系统备份/设备转移明确排除本机 usage.db，避免复制身份或隐私数据。

同一来源历史可能同时从原采集器和旧中心只读导入。设备显示名称/平台别名与导入接收时刻不属于观察内容：相同事件 ID、来源设备 ID、时间与观察字段的重复上传直接确认，不重写中心的显示信息或所有者。不同设备仍不能以同一事件 ID 修改标题、网址、时间或其他观察字段。否则 `OMEN/windows` 与缺少设备表的本机回退 `Meta-OMEN/win32` 会把合法的重复导入误判为跨设备覆盖并返回 500。

浏览器开发版使用 IndexedDB 保存测试或既有历史，只提供查看界面，不能宣称正在本机采集或中心同步。底层导入适配保留给兼容、迁移与隔离测试，不重建面向用户的载入功能。查询分页且有范围上限，超过上限明确报错而不是把残缺结果当完整统计。大量多年历史需要分时间范围，不一次读入 UI。

## 采集与隐私

所有采集、浏览器网址默认关闭，设置只作用本机，不随共享业务设置传播。

- Windows/macOS：`native/collector` 合入 Work Review 的原生 core/agent，不合入旧服务器和 Web UI。Dayweave 在自己的 profile/collector 下生成配置、启动私有子进程，10 秒默认采样、5 分钟默认闲置阈值；锁屏、睡眠断点、闲置与失败不补成工作时长。浏览器关闭时走不读取地址栏的路径。桌面可关闭窗口继续托盘采集；退出会先停止自己的采集器。`--host-managed` 通过 stdin 生命周期检测宿主退出，避免孤儿采集。不会操作旧 Work Review 的启动任务或进程。
- Android：UsageStats 应用切换/锁屏事件形成区间，解锁是瞬时事件，持续区间保留稳定起点并修订终点。首次启用回看系统仍保留的近七天事件；重新启用从当前时刻开始，关闭期间不回填。配置保存、本地状态和时间线查询均触发本机采集，不等待网络同步；一秒内重复请求合并采集窗口。WorkManager 约 15 分钟周期及应用打开时运行；前台借现有同步调度约 15 秒触发自动记录交换，不要求常驻隧道 App，也不承诺系统强制停止后实时运行。
- Android 前台自动交换只保留一个进行中请求，不等待它才进行手动同步；原生自动网络、自动本地查询和原业务网络分别排队。慢速或离线自动上传不能占用原业务网络队列，手动同步错误也不抑制本机观察采集。
- 可选浏览器：用户自行授权无障碍，只观察支持浏览器的原生地址栏；Via 使用原生工具栏结构，拒绝页面 WebView/列表/滚动区和编辑状态候选，不保存页面树、输入内容或执行点击。标题不可得就留空，不捏造。Android 网址观察在授权无障碍服务存活期间约两秒更新。
- AW 旧媒体事件可导入并在自动时间线保留；当前新的 Android 采集器不接入媒体会话监听，不把媒体播放时长加到前台应用时间。
- 采集时过滤忽略应用/域名；敏感标题或网址关键词清空标题和网址。既有历史导入不会被当前采集规则追溯删除。截图与 OCR 在当前整合中固定关闭，不提供图像采集开关；旧 Work Review 的截图、OCR、报告及高级自定义分类配置尚未迁入本次 UI。
- macOS 新采集路径仍须在系统中人工授予辅助功能；Android 使用情况/无障碍/电池权限均只打开系统设置，不代替用户授权。
- 忽略应用使用共享 Modal 内的图标/名称/身份列表、搜索、已忽略筛选与勾选草稿，不再提供逗号文本域。Android 仅查询可启动应用，无 QUERY_ALL_PACKAGES；桌面来自已观察应用。保留未匹配到目录的旧规则，取消不落盘，完成更新设置草稿，保存才写本机配置。域名与敏感词使用可增删标签。

## 历史接入

既有 AW 标准 buckets、手机上传批次、Work Review Activity JSON、Dayweave 自动记录 JSON 适配仍可用于内部迁移。已经配置的 Work Review SQLite / AW 接收目录继续只读接入；移除常规界面和 IPC 文件选择入口，不破坏已有来源配置。

- 外部 SQLite 只读打开，以来源稳定事件键与目标库做去重关联。不能只按 timestamp/rowid 水位：中心可能晚收到更老历史，清理/VACUUM 也会重排 rowid。只对 Dayweave 自己的 collector/agent.db，在已成功进入 usage.db 后确认 synced，允许原生采集器回收其投递缓存；外部库 synced 不变。
- AW 按 `(device_id,bucket_id,bucket_created,event_id)` 标识，保留零时长解锁和结束时间修订。文件接入按文件状态重扫，事务内按事件 ID 去重；不修改源文件。非事件元数据 JSON 不作为记录导入。
- 不按相同设备名强行合并身份。旧 AW、旧 Work Review、新 Dayweave 的独立来源身份可能属于同一物理设备，但没有可靠映射证据；界面可筛选来源设备，后续若加入人工别名必须保留原始来源键。

## 中心与离线交付

沿用已有同步配置、配对密钥、HTTPS 地址/路径前缀与 ROG 中心角色，增加独立 `/usage` 交换；不另建账号或云端服务。请求 AES-GCM AAD 为 `/usage`，回执为 `/usage:reply`，同一 clientId 加随机 requestId 绑定回执。每批最多 300 条上传/500 条下载，最多 20 批后让出；序号游标按中心持久 SQLite 提交推进，旧修订重传幂等。中心限制来源覆盖，客户端只接收其发出的确认项。

接收/确认/游标在同一 SQLite 事务；断网或回执丢失保留 pending，重试不重复。所有已配对设备可拉取全部来源设备的记录；本地采集关闭不阻止查看及同步其他设备。中心与各客户端都需要更新到包含此模块的构建。旧 0.4.3 中心未提供 `/usage` 时，显示自动记录错误但不撤销配对，也不阻塞原有手动数据同步。

自动记录共用全局同步入口，不另放同步按钮或状态摘要。全局「立即同步」并行等待业务数据与自动记录交换，并将实际失败返回现有错误处理；周期调度仍使用各自去重请求和原生队列，慢速自动上传不能阻塞业务重试。Android 从权限设置恢复前台时立即刷新本机状态并允许下一轮同步。

- 测试使用独立临时 profile/数据库。源码测试与隔离 Electron 流程不等于真实系统授权、原生前台窗口采集、Android 后台保活、已安装五端升级或公网同步验收。已部署的版本与验收事实记录在 AGENTS 和部署日志；不得改动旧采集器或伪造系统授权。
