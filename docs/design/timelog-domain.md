# 时间、数据与积分契约

## 时间记录

时间采用 Unix epoch 毫秒存储。每条记录包含有序、不重叠的有效片段 `spans`。
暂停是片段之间的空隙；不能把记录的首尾相减当作有效时长。
日界线由当前设备本地日历计算，下一天使用日历日期递增，不能固定加 86,400,000 毫秒。
因此记录可以跨午夜，夏令时日可以是 23 或 25 小时。

同一时刻可以有多条手工记录。总记录时长、每种性质时长和目标进度采用区间并集，
避免重复计时；活动分布与积分按每条记录累计。不同性质的并集相互仍可能重叠，
不应把三种性质简单相加后声称等于总时长。UI 需说明这个区别。

## 计时状态机

`null -> running -> paused -> running -> saved`。开始时保存活动 ID、性质和积分速率。
运行时的时长为已完成片段加 `now - runningSince`，不依赖 interval 的 tick 数。
暂停、继续、结束均持久化。关闭应用不会暂停；睡眠、锁屏时间也包含在运行片段中。
设备时间倒退时拒绝暂停/保存，保留原计时。时钟向前调整也会延长记录；可保存后编辑。

开始、暂停、结束均在一个 IndexedDB `readwrite` 事务中读取最新状态并提交，
两个窗口不能同时启动两个独立计时。BroadcastChannel 负责通知其他窗口重读。
已经打开的编辑表单使用更新时间检查，发现并发变化后拒绝覆盖。

## 积分和目标

积分为有效小时数乘以记录的 `pointsPerHour`，中间计算不逐段舍入，展示保留两位小数。
活动修改不会重新定价历史记录或已经开始的计时。编辑记录且切换活动时应用新活动规则。
日常活动新建时为 0 分；积极为正，消极为负。这是本项目自定义的积分，未还原官方收入模型。

0.2 界面仅展示记录积分，不提供商店或兑换。为读取 0.1 备份，领域模型保留历史奖励字段。
历史积分余额 = 所有未删除记录的积分之和 - 历次兑换时锁定的积分成本。
兑换在最新持久状态上重新检查余额，余额不足时整个事务不写入。
删除历史记录可能使余额变为负数，兑换历史仍保留。

目标按关联活动的有效区间并集计算，每日或周一开始的每周。归档只隐藏目标，
不删除其关联记录。奖励成本后续修改不改变已经发生的兑换成本。

## 保存与恢复

数据库 `open-timelog`，object store `state`，`current` 存当前完整状态，`previous`
存最近一次成功修改之前的完整状态。单次事务原子提交二者。
所有加载、写入、导入经过结构、类型、数值、引用、ID、时间片段顺序校验。
未知或损坏状态不能自动以空数据库覆盖；提供原始恢复导出。

记录采用软删除标记与单调 `updatedAt`；归档与删除标记参与备份迁移。
本版本不是多设备自动同步协议。IndexedDB 可能受浏览器清理、配额影响，导出 JSON 是
独立的用户备份；浏览器、站点地址、桌面应用的存储彼此独立。

## 备份格式

```json
{ "format": "open-timelog", "version": 1, "exportedAt": "ISO-8601", "data": {} }
```

- UI 最多接收 10 MiB 文件；JSON 先完整校验并预览，再由用户执行合并/恢复。
- 合并按各实体 ID 及 `updatedAt` 保留较新版本；同版本不同内容拒绝整个合并。
- 合并时本机或备份存在计时都应拒绝，避免静默丢失进行中的计时。
- 完整恢复明确替换本机状态，支持恢复进行中的计时；导入前自动下载本机备份。
- 原版 UpTimer 数据不属于此 schema，不能仅靠字段名猜测后导入。
- CSV 防护公式前缀，包含 UTF-8 BOM，时间为 ISO。CSV 是分析导出，不能无损恢复暂停片段。
- Markdown 是本地日期的可读日记表格，按日期截断跨日片段。

## 平台

网页仅加载同源静态资产，生产环境的 Service Worker 缓存完整 app shell。
需 HTTPS 或 localhost 才能安装/离线缓存。开发模式不注册离线缓存。
每次发版应更新 Service Worker 缓存版本，等旧客户端关闭后生效，避免旧网页引用已删除资产。

Windows 使用 `timelog://app/` 固定安全来源，安装路径变化不改变 IndexedDB 的来源。
Electron 启用隔离、沙箱与 Web 安全，禁止新窗口、远端请求和权限请求，preload / IPC 仅开放固定的主题与本机 API 桥接，见 platforms.md。
开发运行数据在仓库 `.runtime/desktop`；测试使用临时的独立 profile；发行包正常运行
使用 Electron 的应用 `userData` 目录。复制程序文件夹不等于数据迁移，迁移请使用 JSON。
