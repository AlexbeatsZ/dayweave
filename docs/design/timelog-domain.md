# 时间、数据与积分契约

## 时间与日界线

时间采用 Unix epoch 毫秒存储，每条记录包含有序、不重叠的有效片段 `spans`。暂停是片段之间的空隙，不能把记录首尾相减当作有效时长。开始时间、结束时间与片段参与同步，不同步每秒 tick。

日期分组、日计划、目标和统计使用用户选择的日程时区，默认 `Asia/Shanghai`；设备系统时区不变。例如设备为 UTC-4、课程为 UTC+8 时，课程、任务日期和记录归日仍按设置的 UTC+8 计算。日界线由所选时区的日历计算，下一天按日历日期递增，不能固定加 86,400,000 毫秒；夏令时日可能为 23 或 25 小时。

同一时刻可有多条手工记录。总记录时长、每种性质时长和目标进度采用区间并集，避免重复计时；活动分布与积分按每条记录累计。不同性质的区间仍可能互相重叠，不能把三种性质简单相加后声称等于总时长。

## 同一计时记录

计时状态为 `null → running → paused → running → saved`。开始时锁定活动 ID、性质和积分速率；可同时保存任务关联 `taskId`、描述及相关标签。运行时长由已完成片段和当前运行片段计算，关闭窗口、锁屏和睡眠不会隐式暂停。

同步中未结束记录的 `timing.endAt=null`，`startAt`、`runningSince` 与 `spans` 表示起点和运行状态。结束时给同一个 ID 保存有效片段，不另外生成无关记录。UI 中的 `timelog.timer` 和 `records` 是这一模型的适配，见 sync.md。

可选 `plannedEndAt` 表示倒计时的计划截止时刻，没有该值则为正计时。新建倒计时至少一秒，运行片段始终截断到截止时刻；到期以相同 ID 保存，延迟唤醒或晚到请求不能延长记录。暂停冻结剩余时间，继续时按暂停持续时间顺延截止，暂停间隔不计入有效时长。`timerPresets` 保存在 `timelog.settings`，默认 `[5,30,45,60]`，可添加或删除；预设为 1 至 10080 的整数分钟，最多 30 项、去重。

`finishDueTimer` 是前台与中心共用的到期收尾规则。前台时钟和恢复前台时检查到期，ROG 的 `StateService` 在加载、读写及已安排的截止回调中再次检查；重复检查不会重复保存。写盘失败保留可恢复状态，不能宣称已经成功结束。离线 Android 后台 WebView 可能被冻结，恢复后按原截止保存，不承诺系统后台即时运行或通知。

调整开始时间不得晚于现在，也不得越过首段结束或计划结束；已有暂停间隔必须保留。“上一条记录末尾”只是填入开始时间的快捷方式。用户明确选择过去的完整起止范围时可保存为结束记录，未来结束时间进入倒计时。

下一个活动通过 `nextActivity` 在同一事务、同一时刻结束并记录当前项，再开始新活动。新活动有自己的 ID，旧活动最后边界与新活动开始边界一致。不能先写一次停止，再异步写一次开始而留下空档。

正常启动、暂停、结束、边界调整与 API 操作走统一 store / `StateService` 写入队列，在最新持久状态上校验。编辑表单以 `updatedAt` 或 revision 检查并发变化。设备时间倒退到运行起点前时拒绝暂停/保存，保留原计时。离线并发启动保留冲突计时，必须由用户处理，不自动丢弃或挑一个结束。

## 任务、活动与颜色

任务计时通过 `startTaskTimer` 共用入口读取所属清单的 `activityId`，锁定活动并带入任务 ID、标题和标签。默认映射为学习 → 学习、工作 → 实操、生活 → 日常，显式绑定优先。配置引用的活动失效时拒绝启动并提示重新选择，不悄悄改变归属。

清单与活动各自保存 `color`，待办和活动标签颜色分别保存在统一状态的 `tagColors.tasks`、`tagColors.records`。标签仍是任务/记录中的字符串数组；颜色元数据允许预先创建未使用标签，不为此新增另一套任务或记录实体。颜色参与校验、备份、增量保存和同步。

删除标签移除其颜色元数据与对应任务或记录/计时中的标签，内容本身保留。删除活动阻止新计时使用，并删除关联目标；若历史记录引用该活动，保留带 `deletedAt` 的身份供历史解析，否则可移除实体。正在主计时或冲突计时中使用的活动不能删除。UI 不提供归档/恢复入口；旧备份的 `archived` 字段仅作读取兼容。

## 积分与目标

积分为有效小时数乘以记录保存的 `pointsPerHour`，中间计算不逐段舍入，展示保留两位小数。活动修改不会重新定价历史记录或已经开始的计时；编辑记录且明确切换活动时才应用所选活动规则。日常新活动为 0 分，积极为正、消极为负，这是本项目积分规则。

目标按关联活动的已保存有效区间并集计算，分为每日或周一开始的自然周。界面展示当前日/周进度，不提供目标日期切换；删除直接移除目标，记录继续保留。不提供商店、结算或兑换入口。历史奖励及兑换字段保留，旧兑换记录中锁定的成本不因后续修改而变化。

## 保存与备份

时织使用一份经过校验的统一状态，任务、时间记录与课程都由同一保存通道拥有；`timelog/storage.ts` 是原模块导入/事务适配，不再拥有独立的 `open-timelog` IndexedDB 数据库。网页、Android 与 Electron 的具体保存方式见 storage.md 和 integration.md。完整加载、保存、导入都校验结构、数值、引用、ID 与片段顺序；损坏数据不能静默变为空状态。

记录删除标记与单调 `updatedAt` 用于历史、备份和同步，不等于产品重新提供回收站或归档功能。JSON 是无损备份；CSV 为分析导出，使用 UTF-8 BOM、公式前缀保护与 ISO 时间，不能无损恢复暂停片段。Markdown 导出按所选日程时区截断跨日片段。

兼容原模块格式：

```json
{ "format": "open-timelog", "version": 1, "exportedAt": "ISO-8601", "data": {} }
```

- 原模块备份合并按实体 ID 与 `updatedAt` 保留新版本，同版本不同内容拒绝整个合并。
- 本机或备份存在进行中计时时，原模块备份合并拒绝操作，避免静默丢失计时；完整恢复先导出本机安全备份，再明确替换。
- 完整时织备份还包含任务清单映射、标签颜色与课程；原 Timelog 备份不包含这些模块。
- 旧 schema-1 备份可由新程序补默认值后读取，不表示旧程序能读取新增字段。中心与客户端需配套更新，见 sync.md。
- 原版 UpTimer 数据不属于此 schema，不能仅凭字段名猜测导入；既有迁移脚本和迁移记录是单独的显式流程。
